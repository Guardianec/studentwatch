# Перевірка Поступу 0.4.1

## Середовище

Порівняно збірку 0.4.0 з коміту `42bca77` зі збіркою 0.4.1. Використано Chrome на Windows і локальний Django з окремою SQLite для кожного запуску. Базовий учительський інтерфейс працював у Chrome з підміною лише транспорту Tauri. Фінальний учительський сценарій пройшов також у нативному WebView2 з реальним транспортом і приватним завантаженням. PostgreSQL для тестів запущено окремо на loopback.

Синтетичний набір містить 91 доступного учня, дві поточні групи з перетином, 363 доступні результати за два роки, каталог конкурсів, підтвердження, уточнення й заявку на вступ. Окремий учитель, архівна група та стороннє членство перевіряють межі. Сценарій додає PDF, формує нове подання та повторно подає виправлення. Тести Django окремо перевіряють відхилені результати, заміну матеріалів і історію. Дані створюються в новій SQLite під `.qa`.

## Порівняння завдань

Таблиця рахує переходи та дії від головної після входу або від явно вказаного екрана. Заповнення фільтра та його запуск рахуються окремо. Прокрутка залежить від довжини списку, тому її не включено.

У сценарії звичайної участі в МАН використано ті самі конкурс, сезон, назву етапу, групу та тип результату. 0.4.0 потребував дев’яти дій від головної, зокрема двох переходів між кроками, ручного сезону й окремого входу до списку. 0.4.1 потребує п’яти дій через готову пропозицію сезону, один екран та швидку дію з головної. Вибір одержувача в обох випадках явний.

Локальні прогони Playwright зайняли приблизно 0,32 с для 0.4.0 та 0,47–0,60 с для 0.4.1. Це час автоматизації на локальному сервері, який залежить від браузерного планування та завантаження сторінки. Ціль близько однієї хвилини для учня ще потребує ручного вимірювання за участю учнів.

## Якість і продуктивність

- Три проходи уточнення охопили навігацію груп і розміщення керування, видимість кнопок і контраст при переході, а також палітру, зерно паперу й візерунок форзаца після відгуку користувача.
- Playwright перевірив пошук за іменем і збереження фільтрів, бібліотеку, заявки, запрошення, пояснення вчителя, повторне подання, підтвердження, додавання PDF і завантаження через WebView2, а також позначення матеріалів переглянутими. Перевірено пряме оновлення сторінки збереженого запису.
- axe A/AA пройшов для огляду, вузького вікна вчителя, головної учня на 320 і 390 px, портфоліо та редактора. Перевірено відсутність горизонтального переповнення на цих екранах та вимкнення руху за `prefers-reduced-motion`.
- У локальному браузерному прогоні огляд після входу з’явився приблизно за 0,82 с. Перша сторінка каталогу учнів, бібліотеки й вхідних показалася приблизно за 0,06, 0,15 і 0,12 с відповідно. Це одиничні локальні вимірювання. Нові академічні сторінки не мають еквівалентних базових запитів для порівняння. Каталог і бібліотека повертають по 20 записів. Файли завантажуються за явною дією.
- Продукційна збірка TypeScript/Vite пройшла. Стиснений JS зріс приблизно з 95 до 100 кБ, CSS — з 4,8 до 5,4 кБ. У проєкті немає окремої команди lint або набору фронтенд unit-тестів. Перевірки сценаріїв зроблено через Playwright.
- Django пройшов 36 тестів на PostgreSQL. На SQLite пройшли 33, три конкурентні тести працюють лише на PostgreSQL. Перевірено розмежування ролей, доступ за чинним членством, приватність чернеток і документів, історію, унікальні підсумки й окремі рішення груп. Перевірка міграцій не виявила змін.
- Tauri зібрав x64 executable та NSIS. Нативний сценарій використовував збірку з адресою тестового API на loopback. Встановлення на чисту Windows не перевірялося. Публічний Render не відповів на запит у відведений час. Деплой і реліз на GitHub ще не виконано.

## Повторити перевірку

За наявності Python-середовища з `server/requirements.txt`, Chrome та Node виконайте з кореня проєкту. QA-пакети встановлюються в ігноровану папку `.qa`.

```powershell
New-Item -ItemType Directory -Force .qa | Out-Null
npm.cmd install --prefix .qa --no-save playwright-core@1.65.0 axe-core@4.14.0
npm.cmd run build
node scripts/qa/workspace.mjs
$env:POSTUP_API_ORIGIN = 'http://127.0.0.1:18141'
$env:VITE_STUDENT_ORIGIN = 'http://127.0.0.1:18141'
npm.cmd run tauri -- build --target x86_64-pc-windows-msvc
node scripts/qa/workspace.mjs --native
```

Параметр `--before` використовує Vite-збірку 0.4.0 у `.qa/0.4.1-before/dist`. Для повторного порівняння зберіть `42bca77` в окремій робочій копії та скопіюйте її `dist` у цей шлях. `POSTUP_QA_CHROME` і `POSTUP_QA_PYTHON` дозволяють перевизначити локальні шляхи до програм. Перед випуском оновіть сервер і звірте health, зберіть клієнт зі справжніми HTTPS-адресами та перевірте встановлення за [інструкцією розгортання](DEPLOYMENT.md).
