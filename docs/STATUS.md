# Стан версії 0.2.0

Учень реєструється в браузері, редагує ПІБ, знаходить групу за кодом і бачить стан заявки. Учитель входить у Windows-програму, створює та редагує групи, копіює запрошення, приймає або відхиляє заявки, переглядає профілі учасників, вилучає учня з групи й архівує групу зі збереженням записів.

Палітру друкованого журналу, типографіку й поділ на список та відомості збережено. Фіктивні записи з 0.1.0 замінено даними API. Досягнення, дипломи, рейтинги та аналіз залишаються в наступних версіях. У 0.1.0 база й облікові записи були відсутні, тому оновлення запускає початкові міграції.

## Перевірки

| Сценарій | Результат |
|---|---|
| Django та PostgreSQL | 12 із 12 тестів пройшли на PostgreSQL 18.6. Серед сценаріїв — реєстрація, CSRF, підміна ролі, чужі групи, обмеження спроб, строки й відкликання запрошень, повторні заявки та одночасне підтвердження. На SQLite пройшли 11 тестів, тест блокування рядків призначений для PostgreSQL. |
| Міграції | Початкова схема створилася на чистих PostgreSQL і SQLite. Для оновлення перевірено сервер із коміту 0.1.0 та міграцію після переходу на 0.2.0. Повторний запуск міграцій завершився без змін. |
| Учнівський сайт | На 375 і 320 px перевірено відображення, реєстрацію, показ пароля, заявку з посилання, перерване подання та підтверджене членство. Перевірки axe на формі та екрані членства не виявили порушень. |
| Windows x64 | На збірці Windows 26300 із наявним WebView2 встановлено окремий пакет «Поступ QA» і перевірено обидва ярлики. Це та сама оболонка з окремою назвою, ідентифікатором і локальною адресою `localhost` для ізоляції від наявного «Поступу» 0.1.0. |
| Наскрізний локальний сценарій | Адміністратор створив учителів у Django Admin. Учень зареєструвався й подав заявку в окремій браузерній сесії при закритій програмі вчителя. Після запуску вчитель прийняв її. Підтверджене членство й сесії пережили окремі перезапуски Django та клієнтів. |
| Збої та облікові записи | Учнівський сайт показав відсутність мережі, Windows-клієнт — недоступність Django. Під час цих збоїв сесії збереглися. Перевірено примусове завершення сесії, вихід і вхід іншим учителем, якому попередня група недоступна. |
| Production-конфігурація | На локальній БД перевірено перенаправлення HTTP, HSTS, Secure/HttpOnly/SameSite для cookie й відсутність дозволу CORS. `check --deploy` пройшов без помилок. Попередження щодо HSTS для піддоменів і preload належать до налаштування конкретного домену. |

Локальний інсталятор — `src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/Поступ_0.2.0_x64-setup.exe`.

## Ручна перевірка за 5–10 хвилин

Підготуйте локальну базу, Django і Vite за [README](../README.md), створіть адміністратора та вчителя. Далі:

1. Встановіть 0.2.0 і запустіть «Поступ» із меню «Пуск». Увійдіть як учитель, натисніть «Створити групу», вкажіть назву і початок навчального року.
2. У відомостях групи створіть запрошення й натисніть «Копіювати посилання». Закрийте програму вчителя.
3. Відкрийте посилання в приватному вікні браузера. Зареєструйте учня. Перевірте, що код залишився у формі. Натисніть «Знайти групу» та «Подати заявку». У списку має з’явитися «Очікує підтвердження».
4. Відкрийте програму знову. Виберіть «Заявки», відкрийте групу й натисніть «Прийняти». В учнівському браузері натисніть «Оновити» і звірте статус «Підтверджено». У кабінеті вчителя відкрийте профіль учасника.
5. Перезапустіть Django, перезавантажте сайт і знову відкрийте програму. Перевірте, що група й учасник збережені. Після виходу з учительського кабінету програма має показати форму входу.

## Обмеження та онлайн-пілот

Репозиторій містить конфігурацію Render Free і GitHub Actions. Онлайн-база Neon під’єднується через `POSTUP_DATABASE_URL`. Після запуску пілоту вчитель може залишити вподобайку у Windows-програмі, а адміністратор бачить її у «Підтвердженнях версій». Перший онлайн-запуск потребує коміту 0.2.0, підключення Render і створення Neon-проєкту. [Покроковий запуск пілоту](PILOT.md)

Після додавання вподобайок пройшли всі 13 серверних тестів на PostgreSQL. У локальному production-режимі Waitress віддав зібраний сайт і стилі адмінки. Вхід і збереження вподобайки працювали з PostgreSQL через TLS, а після перезапуску сервера вподобайка залишилася доступною. Windows-клієнт зібрався з тестовою HTTPS-адресою. Збірка Docker та перше публічне розгортання перевірятимуться в GitHub Actions і Render після відправлення коміту.

- Тестовий інсталятор звертається до loopback. Для онлайн-пілоту потрібні хостинг, HTTPS, PostgreSQL із резервними копіями й нова збірка Windows із робочими адресами. [Інструкція розгортання](DEPLOYMENT.md)
- Інсталятор без цифрового підпису. Інтерактивний майстер, оновлення поверх встановленої 0.1.0 і чиста Windows без WebView2 потребують окремої ручної перевірки.
- Відновлення пароля виконує адміністратор після перевірки особи. Повну офлайн-синхронізацію відкладено.
- При виході без зв’язку Windows прибирає локальний ключ. Серверна сесія може зберігатися до закінчення її строку. У браузері кабінет приховується, а вихід підтверджується після відновлення зв’язку.

Наступний етап за планом — **0.3.0**, довідники конкурсів, досягнення й приватні вкладення. Запропонований коміт — `Додати облікові записи, групи та запрошення у 0.2.0`.
